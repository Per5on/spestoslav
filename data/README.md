# Bulgarian locality and postal-code reference data

## Current import source

Use the GeoNames Bulgaria postal-code export:

- Download: https://download.geonames.org/export/zip/BG.zip
- Dataset documentation: https://www.geonames.org/export/zip/
- Licence: Creative Commons Attribution 3.0 (CC BY 3.0)
- Attribution: GeoNames (https://www.geonames.org)

The importer is `scripts/import_worldpostalcode_bulgaria.py` (the historical filename is retained to avoid breaking existing instructions; it now imports GeoNames and does not access WorldPostalCode).

Run from the repository root:

```bash
python scripts/import_worldpostalcode_bulgaria.py
```

It writes `data/bulgaria_postal_codes.csv` as UTF-8 with BOM for spreadsheet compatibility.

## CSV fields

The CSV preserves the GeoNames source value and provides separate Bulgarian/Latin name columns when the source explicitly uses the `Bulgarian / Latin` convention. Administrative fields are kept at their source levels:

- `oblast_name_source`: GeoNames admin_name1
- `municipality_name_source`: GeoNames admin_name2
- `settlement_admin_name_source`: GeoNames admin_name3 (a settlement-level administrative grouping in some records; partially populated upstream, not the locality name)
- Corresponding source codes are retained where provided.

The locality name comes from GeoNames `place_name`. Do not substitute `admin_name3` for it: one administrative grouping can contain several distinct localities. Rows without an explicit Bulgarian/Latin name pair are excluded by the importer rather than having transliterations guessed.

Missing values remain empty. Do not derive a municipality or settlement from a page title, postal-code prefix, or neighbouring record.

## Important limitations

- GeoNames is a reference dataset, not the Bulgarian Posts' authoritative register.
- GeoNames reports 5,304 Bulgaria postal-code records in its current catalogue; the number of records is not the number of unique settlements.
- The same postal code can be associated with multiple localities, and one administrative grouping can cover multiple localities. Do not deduplicate by postal code or `admin_name3`.
- The settlement-level administrative field is incomplete in the upstream data. Keep it nullable and use an official EKATTE register as the settlement identity/master-data source.
- Review row counts and missing-field counts after every refresh. A successful download does not prove completeness or postal accuracy.

## Official Bulgarian settlement reference

The National Statistical Institute publishes EKATTE archives (Excel and JSON):
https://www.nsi.bg/nrnm/ekatte/archive

The eGovernment open-data portal also lists a CC0 combined EKATTE/postal-code dataset dated 1 March 2022:
https://testdata.egov.bg/data/view/34fa8210-8bbc-472d-9d0f-a1c87b85b528

That combined dataset is older and should be treated as a historical cross-check, not silently merged into the newer GeoNames export. Before production use, record the edition/date and verify any conflicts against the current official register / Bulgarian Posts.

## Retired import

An earlier CSV was generated by crawling WorldPostalCode pages. Its extraction logic mixed page headings into administrative labels. It has been removed and must not be used. WorldPostalCode terms also prohibit automated bulk extraction outside authorised dataset access.
